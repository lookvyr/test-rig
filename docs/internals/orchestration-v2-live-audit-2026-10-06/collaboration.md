## New UI differences for the live comparison

### C1 — Native-child loading state briefly mounts the ordinary composer (P3 continuity; source-confirmed, visual effect unobserved)

Test Rig can render a routed chat from a shell while its detail is loading: `apps/web/src/components/ChatView.tsx:1156–1166` constructs `loadingServerThread`. However, native ownership and parent ID are determined only from `threadProjection` at `:2039–2041`. When the projection is null but the shell is known, `isProviderSubagent` is false and the main render at `:6414` mounts ChatComposer, with **Messages loading** send disablement at `:6513`; the native status bar and parent navigation appear only after projection arrives.

Nightly identifies native ownership from the already available `serverThread.source` (`nightly/apps/web/src/components/ChatView.tsx:2079`), derives parent lineage from activeThread (`:2102`), and keeps the status-bar/composer decision separate from transcript arrival (`:4187–4188`, `:11240–11260`). This provides a stable native child layout and parent return during loading.

Smallest proof: navigate to an uncached native child while transcript fetch is slow, or reconnect into one. Capture whether the editable-looking disabled composer flashes, whether **Open parent** disappears, and whether the overlay height changes. No unauthorized send is claimed: the loading gate disables Send, and the owning server explicitly rejects native child `message.dispatch` at Test Rig `apps/server/src/orchestration-v2/Orchestrator.ts:9088`. Adapt shell ownership/parent derivation; preserve Test Rig's independent fork divider labels.

Test Rig `apps/web/src/components/chat/MessagesTimeline.tsx:4907–4922` keeps these as `SimpleWorkEntryRow`; `:5170–5183` adds the generic **Open subagent** action. The regular subagent task card exists (`V2LifecycleRow.tsx:225`), but there is no `SubagentNotificationLink` implementation. Delivery and navigation are present; the missing part is coherent named completion presentation alongside the spawn/task cards.

Given the current user direction to default new retained-core UX to upstream, this is a concrete presentation port to consider rather than evidence that delegation is absent. Live acceptance: complete/fail/cancel two children, inspect notification identity and preview, open each correct child, then start a child follow-up and ensure old notification status/time stays frozen while hover may show current work.
