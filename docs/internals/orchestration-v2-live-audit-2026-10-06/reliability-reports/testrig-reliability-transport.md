Added `observability/DefectReporter.ts` and provided its layer at the WebSocket boundary: typed failures stay expected responses, while unhandled defects are logged with the failing fiber's logger context. No ACP/cloud/relay paths were imported.

2. **Closing a full stream releases the shared reader.** Extended the existing pinned `patches/effect@4.0.0-rc.115.patch` in both `src/unstable/rpc/RpcClient.ts` and its shipped `dist/unstable/rpc/RpcClient.js`. The stream finalizer obtains its Queue entry, deletes the entry, shuts down the queue, then sends Interrupt. This releases a shared protocol fiber already blocked in `Queue.offerAll` when the consumer closes. Existing request hooks are preserved.

3. **Real Effect toolkit declared failures are MCP errors.** The same narrow package patch updates `src/unstable/ai/McpServer.ts` and `dist/unstable/ai/McpServer.js`. rc115's Toolkit result already exposes `isFailure`; registration now forwards that flag as `CallToolResult.isError`. Declared failures retain their encoded text, and omit success-only structuredContent. Successful object results still expose structuredContent and the advertised success output schema. Unexpected defects retain the existing generic internal-error response and do not leak private defect detail. Production `McpServer.toolkit` registrations all benefit; no custom per-tool registration framework was added.
