## October 7 refresh/checkpoint timeout diagnosis

The combined pre-pause suite timed out in `runtimeLayer.test.ts` at the production run-services refresh/checkpoint fixture. This was a stale direct-execution fixture, not an environment failure or a production deadlock.

The fixture dispatched a message, leaving the durable run in `starting`, then called `RunExecutionService.startRootRun` directly. Real `ProviderTurnStartService` first atomically commits the run, attempt and root node to `running` and its provider thread to `active`. The new terminal ownership guard correctly requires that admitted state. It rejected the fixture's terminal write, so the fixture's `turnRefreshed` receipt was never emitted.

The correction is **test-only**. It asserts the initial `starting` state, mirrors the production admission through `writeIfRunCurrent`, then performs direct execution. It also asserts `waiting` after the native terminal receipt and `completed` after checkpoint finalization. No production guard was weakened, no timeout was increased, and no sleep/polling was introduced.

The first root-level test command also discovered an incomplete task-created source backup under `.test-rig`. That exact captured session was stopped. The primary removed only that duplicate directory while retaining the canonical backup archive; package-directory focused runs avoided duplicate discovery. This discovery issue was separate from the fixture diagnosis.
