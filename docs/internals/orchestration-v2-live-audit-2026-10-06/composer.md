## Source-backed presentation gaps to verify live

### G1 — Manual Codex compaction is implemented but undiscoverable, and has no draft-preserving UI action (P2 UX)

Test Rig Codex adapter already calls `thread/compact/start` in `apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts:5667`. Its Codex provider snapshot at `apps/server/src/provider/Layers/CodexProvider.ts:614` supplies models and skills without slash commands; `apps/server/src/provider/providerSnapshot.ts:244` defaults an omitted catalog to empty. Composer built-ins at `apps/web/src/components/chat/ChatComposer.tsx:1042` include `/side`, `/model`, and gated `/plan`/`/default`; provider commands are only appended at `:1080`. `apps/web/src/components/chat/ContextWindowMeter.tsx:15` has no compact callback and its popup ends at `:140`.

Nightly `apps/server/src/provider/CodexProvider.ts:692` advertises `COMPACT_SLASH_COMMAND`. `apps/web/src/components/chat/ContextWindowMeter.tsx:152` adds `Compact context`; `ChatView.tsx:7203` sends `/compact` separately while preserving typed draft and attachments. The composer guards compact during active requests/run at `ChatComposer.tsx:4246` and hides invalid mixed-context `/compact` menu choices at `:2543`.

Suggested upstream UX: advertise the existing Codex command and adopt the context-gauge action, disabled reason, and standalone draft-preserving command route. Keep existing Test Rig compaction timeline. This closes an existing capability's affordance gap and needs no native-goal decision. Live C10 determines actual installed behavior and provider catalog contents.

### G2 — A not-resumable question still offers interactive response controls (P2 correctness/presentation)

Test Rig `ComposerPendingUserInputPanel.tsx:11` takes request/answer/responding props but does not use response capability. `:133` gates number shortcuts only on responding/global shortcut state; option buttons at `:225` disable only while responding. `ChatComposer.tsx:1250` builds primary question action without a capability block; `usePendingUserInput.ts:148` advances and sends a complete final answer. `ChatView.tsx:5535` dispatches without a capability check. Server `apps/server/src/orchestration-v2/Orchestrator.ts:6691` rejects not-resumable requests. By comparison, the adjacent Test Rig approval UI already checks capability (`ChatComposer.tsx:2881`) and explains lost provider process (`ComposerPendingApprovalPanel.tsx:62`).

Nightly `ComposerPendingUserInputPanel.tsx:67` calculates `canRespond`, `:145` disables global shortcut interaction when not resumable; `ChatView.tsx:3386` and `:9848` block final response. Suggested upstream UX: share this recovery gating across question options, keyboard shortcuts, custom answer, auto-advance and primary action; expose why the request cannot resume and the appropriate Stop/restart recovery action. Live C09 requires a request that remains pending after provider loss; no provider was stopped by this subaudit.

### G3 — Active-turn send looks like ordinary send, including when disabled for unavailable steering (P3 UX clarity)

Test Rig `ChatComposer.tsx:687` turns unavailable follow-up into disabled reason `Send message`. `ComposerPrimaryActions.tsx:238` always labels ready sends `Send message` and `:255` always renders ordinary upward arrow, despite `isRunning`. Workflow `packages/client-runtime/src/state/threadWorkflows.ts:37` correctly forbids unavailable steering and never silently queues. Thus policy is clear in source but ambiguous at the point of interaction.

Nightly `ComposerPrimaryActions.tsx:255` distinguishes `Submit message`, `Steer message`, `Queue message`, `Resume thread`; `:276` supplies state/modifier tooltip and `:313` uses bent arrow for steer. Suggested adapted upstream UX: use the Steer label/icon/tooltip for Test Rig active sends; explain waiting for steer readiness when disabled. Do not import queue/modifier-to-queue because `FORK.md` expressly excludes interactive queueing.

### G4 — Tall provider questions occupy the composer without an upstream collapse affordance (P3 layout)

Test Rig `ComposerPendingUserInputPanel.tsx:165` always renders full question and all options; nightly `:178` wraps question in Collapsible, `:186` labels Show/Hide, `:78` scopes collapse to current question so the next question expands. This applies to retained structured user-input behavior and is a reasonable direct presentation port. Primary live C08 should judge impact at matched normal and short desktop window sizes. Do not copy dismiss action indiscriminately: nightly `:209` shows it only for `prompt.dismissible`, and that request semantics addition needs the owning contracts/server path.

### G5 — Composer lacks the upstream length preflight and actionable inline error (P2/P3 intake)

Test Rig defines `PROVIDER_SEND_TURN_MAX_INPUT_CHARS = 120_000` at `packages/contracts/src/chatAttachment.ts:13`; provider contract enforces it at `packages/contracts/src/provider.ts:72`. The current composer/send path has no length preflight: `ChatView.tsx:5095` prepares context, then starts local dispatch at `:5225` and later builds outgoing provider text at `:5252`. The V2 message contract also contains unconstrained string fields; do not claim a particular end-to-end failure without live/targeted validation of the actual V2 provider path.

Nightly `apps/web/src/components/chat/composerSubmission.ts:12` checks expanded prompt length and gives exact excess count; `ChatComposer.tsx:4181` preflights normal submissions and `:6467` validates final composed provider input; `ComposerPromptLengthValidation.tsx:6` renders inline `role=alert`, and editing clears/recomputes it at `ChatComposer.tsx:3370`. Suggested upstream UX: port preflight plus final composed-input guard and draft retention, not merely an error label. Live C12 should stop at preflight, avoiding a huge live provider request.

## Intentional deviations and exclusions

- Interactive queueing, queue edit/reorder/promote controls, alternate send-to-queue shortcuts are explicitly excluded by Test Rig `FORK.md`. Use upstream steering presentation selectively.
- Rewind/edit-by-truncating-history and checkpoint restore are excluded. Durable fork from earlier response is retained; do not use nightly resend/rewind UX as a composer deficiency.
- Native goals, richer file attachments and prompt recall are new features, not missing preservation acceptance. Their UX should generally follow upstream if selected by the user.
- Plan mode remains gated behind Settings → Beta in both source trees. Build/Plan, Refine/Implement and Implement in a new thread already exist. The previous image/refinement restoration fixes remain in Test Rig and should be tested, not reintroduced as unfixed claims.
- Usage/pricing/cost controls are excluded; context token meter/compaction are retained and can be adapted independently.
- Managed install/auth/update notifications and excluded providers are out of scope. No provider setup/install UI should be imported just to match nightly layout.
- Nightly multiple-model draft selection is specifically enabled by `serverConfig.environment.capabilities.requiredWorktreeBootstrap === true` (`ChatView.tsx:11264`), not ordinary local desktop mode. Its absence in Test Rig's local composer is not established as a local parity gap by this source review.
- Nightly provider runtime-mode filtering is present (`ChatComposer.tsx:2133`), but this source review did not establish any incorrect displayed choice for the three retained providers. Treat provider-specific behavior as live acceptance rather than calling all-mode display a defect.
- New continuous shimmer/animated resting composer treatments need separate performance assessment; Test Rig's repository taste rejects continuously repainting effects. Do not import motion just to achieve screenshot parity.

## Suggested order after live evidence

1. Fix lost-process question interaction and adopt Codex manual-compaction discoverability/draft-preserving action; these improve existing capabilities.
2. Adopt steering label/icon/disabled explanation and collapsible tall question presentation.
3. Select newer native goals, explicit stopped-thread resume, prompt recall, attachments; reuse upstream UX and port complete vertical slices.
4. Keep intentional queue/rewind/cloud/cost divergences explicit in final audit and tickets, avoiding a giant generic parity issue.
