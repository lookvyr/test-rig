## Correctness and scope conclusions

The settings helper rename preserves the original implementation and removes the case-insensitive module collision directly. It does not change resolver order or add compatibility machinery.

Collaboration reuses existing subagent cards and hover presentation. Notifications keep historical outcome/time separate from live hover state and retain a generic fallback when the parent has no child record. App-child effort/speed labels require matching model/account and app-owned origin; native children do not borrow saved parent traits. Shell identity fixes only the loading presentation; the existing owning-server read-only protection remains.

Lifecycle actions reuse existing commands and a shared menu across header/sidebar entry points. Custom snooze uses the existing resolver and one dialog host; it also reaches selected-thread controls. Automations reuse the live task subscription and existing Settings deep links. Enable is a partial update, so it does not overwrite task edits. The watch control stops watching without unlinking, and its settled-state description preserves current pause behavior. These additions do not introduce another scheduler or settlement model.

Files uses actual immediate directory children behind the existing workspace path boundary; the bounded search index remains for search/mentions. Directory requests are limited to four concurrent loads and cache visited folders. Error/retry state preserves cached contents. Resource identity and keyed directory mounts prevent another workspace's cache from being reused. Mutation refresh waits for local editable saves and preserves Review selection instead of auto-opening or resetting scope. Media uses the existing signed workspace asset path, and CSV/TSV rendering remains bounded with an editable source view. No recursive full-tree expansion was introduced as the normal browsing path.

Named-project creation atomically claims a new directory, scaffolds local Git/files, and reports a first-commit failure without discarding the created project. Cleanup is confined to its unused claimed folder; it checks registered ownership before removing after a rejected create and does not remove a potentially committed project on an uncertain interruption. Name collision handling is concrete local filesystem behavior. Publishing stays a separate explicit Git action. Draft defaults resolve the destination project/environment while retaining intentional model/permission choices, rich content and the existing terminal retarget lock.

Closed-view restoration has a bounded twenty-entry history. Catalog-ready versus live-shell checks correspond to actual discovery/reconnect/removed-owner states. Already-open entries are dropped; failed restores are retained/deferred without background retry. Terminal processes are not resurrected. Incognito entries can exist in session memory but are excluded from persisted history. Browser metadata survives restoration. Shared launcher shortcuts are guarded for typing and visible dialogs; keep-mounted hidden popovers and the inline complementary Details card do not suppress them.

Browser profiles preserve the existing Default partition while giving named profiles distinct scoped partitions and Incognito nonpersistent storage. Guest config is keyed by environment/profile before attachment. Audio state is owned by the matching native WebContents and muting targets one tab. Scoped cookie/cache clearing targets the chosen environment/profile; legacy no-argument clearing remains compatible. Main-window zoom and sender-owned Paste-as-Text handling belong to the desktop boundary. The implementation does not require a server-hosted browser migration.

## Simplification and excessive-defense assessment

The largest requested simplification was completed: recall delegates context interpretation to the existing owner instead of maintaining another parser. Other new helpers remain focused on real seams: asynchronous draft ownership, workspace mutation invalidation, native browser partitions, user-close confirmation and closed-view restore planning. No unnecessary generic retry framework, duplicate settings editor, alternate queue model or new orchestration layer was identified.

The retained guards have concrete reasons: route/request generations protect user intent; workspace realpath checks protect the owning root; native audio/WebContents and clipboard sender checks protect native ownership; capability flags handle actual older-server support; model/account/origin checks prevent false trait labels. Their scope is narrow. No extra hypothetical-risk approval flow was added.

FORK boundaries remain intact: no interactive follow-up queue UI, rewind/edit-by-truncation, checkpoint restore, merge-back, recursive child Stop, excluded providers, cloud/relay/mobile, usage/cost dashboards, telemetry or managed provider installation. Existing rich drafts, Review scopes/staging, Find, PR link/unlink, side chats and durable side forks are preserved. New goals/HTML/secret flows and arbitrary non-image attachment delivery were not silently added to this implementation.

The proposed 120,000-character preflight was correctly rejected after checking that current V2 does not enforce that legacy provider limit. Its absence is not unfinished repair work; imposing it would have added an unsupported new restriction. Image picker wording stays image-specific.

## Final native-browser integration follow-up

The primary's later live pass found two additional integration failures after the original review snapshot. Both final repairs have now been independently source-reviewed; no remaining actionable finding was identified in them.

1. **Scoped clear data survived the transport codec.** The old `Schema.Union([Schema.Void, DesktopPreviewConfigInputSchema])` accepted an actual config object through the Void alternative and decoded it to undefined. The handler consequently took its legacy global-clear path, despite a correct native partition filter. The final exported `DesktopPreviewClearDataInputSchema` uses `Schema.Undefined` instead, and both cookie/cache IPC methods consume it. Its regression verifies that `{environmentId, profileId}` remains an object, undefined still supports legacy global clearing, and profile-only input without an environment rejects. This is a genuine cross-boundary correction; the earlier partition-filter source review alone did not establish that wire decoding was safe.

2. **The externally hosted guest has a scoped Sheet layer.** The original guest layer30 was under a Sheet at50, and Sheet modality applied global inert/aria-hidden behavior to the separately hosted native browser. Only the active desktop-supported Browser panel path now opts out of right-panel Sheet modality; other right-panel paths and other Sheets retain default modal behavior. `SheetPopup` gained one layer prop applied to both its backdrop and viewport, default50. The right-panel Sheet alone uses `RIGHT_PANEL_SHEET_LAYER=40`; its hosted guest follows at41, while inline guest30 remains. Ordinary dialogs50, menus60 and higher popovers stay above it. This also resolves the review's concern with the initial guest51 workaround, which would have put the browser above ordinary dialogs. No global Dialog change, global nonmodal policy, popup observer or reparenting mechanism was added.

The layer flows through the existing owning surface lease/store and wrapper style, so a surface move changes its presentation consistently rather than replacing the guest. Hidden guests retain the existing offscreen/pointer-disabled behavior. The primary reported fresh native profile cookie-clear isolation and narrow-browser interaction checks; those are primary live observations, not the reviewer's observations.
