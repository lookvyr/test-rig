Primary-agent observations are explicitly attributed below rather than treated as this review's observations.

The reports generally identify real source differences and correctly distinguish Test Rig policy from upstream parity. The biggest improvement needed in a final report is priority language: a missing upstream feature, a backed capability with a missing human control, and an observed build failure are different kinds of work. Do not flatten them into one P2 parity backlog or reopen broad Done tickets solely because the newer upstream has more controls.

## Backed affordances and lower priority parity

- **G1 Codex compaction discovery: P2 UX**, strengthened by the primary's successful `/compact` and absent slash-menu entry. The capability exists; advertising it is smaller than a new compaction subsystem. The nightly `ContextWindowMeter` contains a conditional Compact button, but the primary's actual nightly desktop instance had no context gauge. Accordingly, the gauge button's availability and draft-preserving route remain source-backed, not observed desktop parity. Preserve existing drafts/attachments and current compaction timeline; do not import the nightly cost row, which is excluded.
- **Stopped-thread Resume: P2 UX backed by existing server support**, rather than a completely absent continuation system. Current contract includes `manualContinuationOfRunId`, `Orchestrator.ts:4370+` validates it, and `runtimeLayer.test.ts:4298` exercises it. The composer lacks the button, as the primary observed. Port the eligibility/empty-composer action and current runtime command. Do not show Resume on every normal completed thread, manufacture automatic goals, or blindly expose upstream held interactive queues.
- **A1 thread-bound automation details: P3 default priority**, useful convenience and ongoing-task visibility over already functional Settings controls. Reuse one live subscription filtered by scoped thread, the existing edit deep link, partial enable and run-now commands. Keep failed subscription visible. Do not import webhook-only types or build another task editor inside chat.
- **A2 custom snooze: P3 default priority**, a source-confirmed incomplete affordance over the existing validated resolver. Preset snooze/Wake already works. The primary corroborated no Custom entry. Reuse one shared dialog host and resolver across header/sidebar/bulk entrances; do not call all snoozing broken or invent another timer model.

## New features and policies

W1 create-project-from-name, W5 media/table viewers, W8 browser profiles/audio, native goals, sent-prompt recall, non-image attachment picker, HTML tool results, and dismissible request cards are newer additions. They have valid local uses and are not automatically prohibited, but their absence is not proof the original V2 preservation work failed. Reuse upstream UX when selected and port the owning contracts/adapters/assets/persistence/IPC as applicable. Name-to-project creation should keep local creation distinct from optional explicit private publish, with hosting toggles. Media/table preview is separate from the real W5 error/retry gap, which can be repaired without implementing new players.

Named browser profiles/audio must fit Test Rig's existing desktop preview owner and independent partitions. Do not infer that parity requires the newer server-hosted browser migration. Native goals need durable contract/projector/adapter/recovery support; `/goal` as plain text is not equivalent. OpenCode support must be stated explicitly. HTML results are a new toolkit/rendering feature, not a Markdown tweak.

The secret-card report correctly identifies the pinned nightly's actual consumer as excluded webhook signing. A private secret request capability can be evaluated later for a retained local consumer; it is not currently a required scheduling repair. Interactive follow-up queue UI, rewind/restoration, merge-back, cloud/relay/mobile, usage/cost dashboards, managed provider install/auth and unsupported providers remain exclusions. Multi-model composer work gated by requiredWorktreeBootstrap is not established as a normal local-desktop parity gap. Continuous resting shimmer is in tension with the repository's explicit performance taste and should not be imported for visual matching.

The collaboration report's caution on the parent background banner is correct. Its Stop text may imply broader cancellation than selected policy, but a real banner/task/entity/child mismatch has not been established. Keep it as a focused live probe and possible wording correction, not a second cancellation bug. The prior recovery bookkeeping defect is separately confirmed and should not be relabeled as a new live Stop failure. Durable side forks, explicit parent navigation, richer Review scopes, scratch terminal retarget protection, quota recovery, and independent app-child Stop behavior should remain preserved.

## Suggested small implementation order after audit

1. Repair the confirmed macOS build collision.
2. Repair misleading/unusable existing states: recovered question gating, applicable project defaults, lifecycle/watch controls, Files resource navigation/refresh and server/runtime reliability findings from the earlier audit.
3. Add compact discovery and backed Resume; then automation details/custom snooze, steering labels, keyboard access, notification presentation and terminal/menu improvements.
4. Select the larger new features independently. Each should have one cohesive owning slice and the smallest relevant provider/desktop/renderer acceptance, followed by the user's requested independent simplification review for nontrivial changes.

No source report was rejected wholesale. No current source finding should be described as a live observation unless the primary captured that specific transition. The strongest priorities are actual build/correctness failures and missing ways to inspect/stop already ongoing behavior; screenshot parity alone does not set severity.
