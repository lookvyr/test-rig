This report records gaps and an implementation order; production source and Linear were not changed.

## Highest-priority findings

### P1 — Current macOS desktop build fails

`BranchNamingSettings.tsx` and `SourceControlWritingSettings.tsx` import `./ProjectSettingsScope`. The component is `ProjectSettingsScope.tsx`, while the helper is `projectSettingsScope.ts`. On the case-insensitive macOS filesystem, extensionless `.ts` resolution selects the helper, which has neither `ProjectSettingsScope` nor `useProjectSettingsScope`. The real web build failed with missing-export errors before desktop could launch. Mocked component tests conceal this linkage problem.

To continue the requested audit, the primary created a disposable source archive and made those two imports explicitly end in `.tsx`. The resulting web/desktop build launched and powered the live pass. This is **not evidence that the pristine checkout boots successfully**. The durable repair should rename the helper to `projectSettingsScope.logic.ts` and update helper imports/tests. Do not change global resolver order. [Owning-source/filesystem proof and exact locations](orchestration-v2-live-audit-2026-10-06/workspace.md#w0--p1-macos-desktop-build-is-blocked-by-case-insensitive-settings-module-resolution).

## Intentional differences to preserve

- Interactive follow-ups steer; no queued interactive composer UI. Scheduled/internal queued work remains supported.
- Durable independent forks replace rewind/edit-by-truncation, checkpoint restoration and merge-back. `/side` and durable side forks remain Test Rig features.
- Parent Stop does not recursively cancel independent app-owned children; it suppresses result wakeups under the accepted policy. This policy was read, not newly stress-tested here.
- Keep richer Review scopes, Test Rig sidebar presentation, Markdown/rich drafts, Find, PR link/unlink, no-project schedules and explicit task permissions.
- Preserve Codex, Claude and OpenCode scope; excluded providers, cloud/Clerk/relay/mobile, usage/pricing, telemetry and managed install/auth are not parity gaps.
- Webhook scheduling remains excluded. The newer private-secret card's actual upstream consumer was webhook signing; it is not a required repair for retained timed tasks.
- No continuous resting animations just to match nightly. Browser profile UX does not itself require adopting the newer server-hosted browser architecture.

These boundaries come from [FORK.md](../../FORK.md), current local policies and the accepted decisions documented in the earlier audit. The user's latest direction sets upstream UX as the default for new retained features, rather than reopening each cosmetic choice.

## Coverage limits and next work

The four source auditors covered composer/requests, collaboration/forks, automation/lifecycle, and projects/files/panels/desktop. A separate reviewer checked severity, owning code and proposed simplifications. The workspace auditor ran **45 focused tests in 4 files**, all passing; the exact command is in its appendix. No repository-wide checks were run. Test Rig's pristine desktop build failed; only the disposable workaround build passed.

Not exercised live: crash/restart during active work or pending input, quota exhaustion/reset, schedule overlap/edit races and restart persistence, nested cross-provider delegation, parent Stop with independent children, active approval cancellation, late Stop(A)/new run B, remote/tunnel/multi-environment connections, PR publishing/watch behavior, attachment edge cases, new goals/HTML/secret flows, large-tree limits, browser-guest zoom, full keyboard entry-point parity or performance benchmarks. There are no timing videos; Stop/steer conclusions are limited to observed state transitions. The earlier audit's runtime/RPC/Claude recovery/scheduler/Git findings remain separate work.

Recommended implementation order:

1. Fix the macOS module collision and verify a pristine supported-macOS desktop build.
2. Address existing correctness: recovered-question gating, source-backed defaults/Files behavior after targeted repros, missing archive/auto-settle/watch controls, plus the earlier audit's runtime recovery/transport/scheduler repairs.
3. Add compact discovery and backed Resume, then custom snooze/automation entry points, steering labels, question collapse and named completion cards using upstream UX.
4. Port larger local capabilities as complete slices: filesystem navigation/viewers, create-from-name, reopen closed views, goals and HTML. Retain Test Rig's explicit policies. Give nontrivial changes an independent simplification/review pass.
5. Rerun the affected matrix and close the OpenCode, recovery and desktop-specific acceptance gaps. Keep completed historical Linear issues intact; create narrow follow-ups rather than treating all V2 work as incomplete.
