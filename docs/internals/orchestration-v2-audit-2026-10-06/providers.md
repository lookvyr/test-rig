## Concrete narrow followups

### P1/P2: Claude fresh-native fallback incorrectly resumes a never-created session

Source: `apps/server/src/orchestration-v2/Adapters/ClaudeAdapterV2.ts:6890` uses `providerTurnOrdinal > 1` as evidence that a native session exists. `ProviderTurnStartService.ts:664` deliberately drops the old native reference on failed resume and creates a replacement while preserving the provider-thread row; `ProviderTurnStartService.ts:1240` still calculates ordinal from all prior turns on that row. Therefore the replacement gets `resume: <new-native-id>` rather than `sessionId: <new-native-id>`, so recovery can fail instead of recreating the native history.

Upstream repair: `efecd3cf8bcec3d1891b5f5a27dc2f6d797c6448` introduces `nativeThreadHasTurns` through ProviderAdapter, ProviderTurnStartService, RunExecutionService and Claude, including legacy-identity safeguards. This patch is absent locally. Local existing provider-switch deterministic adapters pass because they do not exercise the real Claude query-option decision.

Disposable regression: `/private/tmp/testrig-provider-audit-tests/ClaudeAdapterAudit.test.ts`; copied test harness from the real Claude unit file, imports point at current repository source. Allocates a fresh native ID with ordinal 4, supplies `nativeThreadHasTurns:false`, and expects creation rather than resume. Fails: sessionId is undefined and resume is chosen. This is deterministic option selection evidence, not a live CLI failure claim. Recommend a narrow recovery followup; do not reopen all of LOO-27.

### P2: Equivalent Normal selections block Claude followups while background work is active

Source: `apps/server/src/claudeModelOptions.ts:41` leaves omitted fastMode undefined; explicit `false` becomes `{fastMode:false}`. `claudeModelOptions.ts:57` includes those settings in `queryIdentity`. `ClaudeAdapterV2.ts:6849` only reuses the live query when query identities match; `ClaudeAdapterV2.ts:6864` rejects replacement while native background shells/subagents remain live. Choosing explicit Normal after omitted Normal therefore behaves like a changed mode and refuses the next prompt, despite both meaning Normal.

Disposable regression `/private/tmp/testrig-provider-audit-tests/FastModeAudit.test.ts` compares compileClaudeModelSelection identities for omitted versus false on claude-opus-4-6. Fails with `{settings:{}}` versus `{settings:{fastMode:false}}`. Same upstream `efecd3cf8` normalizes omitted Normal to false and adds a background-query reuse test. Recommend the small normalization plus meaningful reuse regression.

### P2: Stop after a failed followup start cannot reach earlier accepted background work

Source: `apps/server/src/orchestration-v2/Orchestrator.ts:7810` searches only turns whose runAttemptId equals the latest run's activeAttemptId. A failed start has no provider turn, even though that provider thread may retain accepted background work. Later `Orchestrator.ts:7998` rejects interruption when no turn is found. Upstream `efecd3cf8` adds a fallback to that provider thread's latest accepted turn when background work exists. This is a high-confidence missing repair from source; not separately replayed by this provider audit. Parent lifecycle auditor should consolidate it with Stop review.

### P2: Codex reported child-model metadata uses the old response shape

Source: `apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts:1249` decodes required top-level `model`; `CodexAdapterV2.ts:2657` probes only `thread/resume`, silently swallowing errors and never checking `thread.model`. Newer Codex metadata can report the model inside the thread. Upstream after-nightly `eea9f7cfebbdb51d27f07a816119c71a67509997` reads `thread/read` first, validates child identity and nonblank thread.model, then falls back to legacy resume metadata. Local tests only provide the old response shape. Scope is truthful child model labels, not transcript identity/parent ownership. Source comparison establishes missing support; no current-provider live reproduction claimed.
