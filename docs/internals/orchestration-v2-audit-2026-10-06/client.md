## Genuine new retained-core gaps / intake candidates

### C1 — Closed IndexedDB connections never recover; abort-only failed commits may leave writes pending (P2)

`connection/storage.ts:120` opens once; `:383` retains that database until layer release. Reads/writes/removes use it directly at `:157`, `:174`, `:189`, `:204`, without close/versionchange invalidation, reopen or transaction-creation exception conversion. A browser-closed database throws `InvalidStateError` on every subsequent access. Writes listen to `error` and `complete`, not `abort`; an abort-only quota/commit failure can leave the Effect unresolved. This affects retained local cache/catalog persistence, including desktop renderer caches, and fits the local product boundary.

Upstream `9c49228f5` / PR #16311 adds a shared lazy handle, close/versionchange invalidation, typed synchronous error handling, one reopen retry on stale connection, and abort completion handling. Adapt the local persistence portion; do not import upstream relay/GitHub routing additions.

Proof: three disposable diagnostics ran against unchanged production source. Two demonstrate consecutive closed-database reads failing and writes registering no abort listener, without real database modification or timeout-dependent tests. Existing `connection/storage.test.ts` passes but covers catalog sanitization/secure-store failure only; it has no closed database/abort recovery test. Full fake-IDB close/versionchange/reopen, concurrent access, abort and acquisition failure tests are the proper next acceptance.

### C2 — A failed secondary bootstrap exchange after token change can drop a usable desktop environment and drafts; rejected credentials are retried every poll (P2, desktop secondary-backend path)

`connection/platform.ts:487` combines endpoint and bootstrap token into one cached registration signature. `:512` only retains an otherwise usable bearer if that combined signature is unchanged. If the token changes and its exchange fails, a valid existing bearer is excluded from the returned registrations. Registry reconciliation removes the omitted platform environment and calls owned-data cleanup (`client-runtime/src/connection/registry.ts:467–505`); Test Rig cleanup clears that environment's composer drafts (`connection/platform.ts:537`). Also, a permanently rejected bootstrap is retried on each 3-second poll (`:324`, `:497`).

Upstream `f36df1852` / PR #16273 separates endpoint validity from bootstrap exchange signature, keeps unexpired bearer registrations across failed rotations and backs off rejected credentials, retrying immediately when token/endpoint changes. The current Test Rig does not have periodic rotation machinery from newer upstream, so describe the trigger as any new token/backend configuration rather than claiming rotation currently occurs every 12 hours. Secondary WSL/local backend is narrower than ordinary macOS primary startup. Source confirms the consequence; no live WSL or rotated-token browser case was run. Adapted unit tests for registration retention/backoff plus draft retention are needed.

### C3 — Rich editor lacks outside caret stops at styled paragraph boundaries (P2 polish)

`ComposerPromptEditor.tsx:412` handles inline atom boundaries only. It has no stored-mark edge stepping for bold/code/italic, and the serialized document exposes marker decorations rather than editable marker text. At the beginning of a pasted `**bold**` paragraph, typing a prefix inherits bold; ordinary ArrowLeft at the paragraph start cannot move to an unstyled stop. The existing shortcut can manually toggle formatting, but it does not provide the expected cursor behavior.

Upstream `d0dc45885` / PR #13217 adds styled-edge caret stops and tests to `composer-rich-text-doc.ts` and its editor. Disposable ProseMirror diagnostic against Test Rig's actual document builder reproduced `prefix ` becoming `**prefix bold**` and proved explicit empty stored marks yield `prefix **bold**`. No browser reproduction was performed in this audit; adapt to Test Rig's `ComposerPromptEditor.tsx`, which differs from the newer upstream file, and verify Home/ArrowLeft/Right, code, nested styles and rich draft persistence.

### C4 — Native bearer bootstrap transient retry (small follow-up candidate; not fully reproduced)

`apps/desktop/src/backend/DesktopLocalEnvironmentAuth.ts:70–85` makes a single exchange and returns error immediately on transient fetch/timeout/502–504 failures. Upstream `76d3c96fd` / PR #12919 retries transient failures within a 15-second bound, while failing rejected credentials immediately. Current native auth tests pass but lack transient retry cases. This is retained local behavior and a reasonable resilience intake, separate from LOO-39. Do not claim every transient failure is unrecoverable: a later caller can try again. No native startup failure was reproduced.
